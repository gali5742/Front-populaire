## 2. 玩家身份及领导层连续性（核心候选）
玩家采取当前SFIO中央领导层的制度性决策视角，而非操控固定人物、固定派系、全体CAP或全党。中央领导层不是额外历史机关；玩家可使用的发起、代表、执行、协商权限均来自实际职务、程序与有效授权。CAP本身为集体议事机关，不能由玩家直接填写支持票。党组、议会党团、总书记、CAP、全国委员会、大会及地方联合会的成员关系、代表权及职务时点分别保存。
建议采用机构视角连续性：领导层失去某项表决或不再拥有稳定多数，不自动失去玩家控制，也不自动撤换总书记；只改变真实决议、合作基础及可用权限。发生合法的领导层改选或任免时，玩家视角跟随当前合法中央领导机构，新的任职者及路线、权限、内部异议须由实际程序产生；旧领导层转为自主政治主体或按真实状态处理，既往承诺与党资金归组织而非个人。玩家仍可依法推动修订，不能借更替自动取消有效决议、协议或恢复旧权限。这是模拟设计选择，并非史实；代价是玩家不是永久扮演某派系。若旧领导层辞任、新任未确定，使用实际合法代理/集体执行权限；无权事项等待制度处理，不凭空授予临时全权。合法程序下仍须有D1零资源回应。党组织整体解体、被取缔、合并导致玩家主体消失的处理留M-07/D8，不预定结局条件。任免机关、提名、选举、代理权限及开局名册待史料核证；不要发明固定现代主席团。

### 2.1 D3-R01 在途事务承接与新领导层约束
合法更替时，事务及其资金、实际记录与义务原则上归属SFIO组织，不因任职者变动而重置。对个人名义的事务或仅限原任职者的授权，须依据实际权限另行判断承接资格，不将个人承诺自动转为全党义务。权限按新任职者、实际生效的集体决议与组织程序重新校验；不是按隐藏人格或派系标签锁定玩家选项。
| 在途事务 | 承接规则 |
|---|---|
| 已安排尚未执行的行动 | 保留实例，执行前重新校验；条件失效则停止执行、释放尚未使用且可撤销的预留，记录原因 |
| 正在执行的长期工作 | 保留历史进展及已支付经费，核验继续、调整、暂停或终止的权限；按D1处理付款义务及预留 |
| 已发出提议、等待回应 | 保留等待状态和实际成本，可接收合法到达的回复；进一步接触、改约、接受或签署分别检查权限 |
| 尚未签署或尚未生效的协议 | 核验签署、生效的实际程序及当前授权，不将前任接触权当成现任缔约权 |
| 已生效的外部协议 | 独立保存实际义务；由D4处理继续履行、改约、退出或违约，不自动失效 |
| 已发生的行为和政治结果 | 保留原有发生时间、执行者、成本及结果；不回滚、不退款、不刷新行动额度 |
更替不自动取消全部在途项目，也不默认继续执行全部安排。新的有效路线约束未来行为；玩家仍可依法提出不同意见、争取修订决议或在现有授权内采取行动。新多数联盟不是固定一致投票集团。等待回复与作出新承诺是不同权限；无签约权不得签约，但不得因此吞掉已发生的对方回复。具体任免、代理和组织整体失去连续性的规则仍留原有未决项。

## 3. 机关及权力分工（候选接口，不是完整历史章程）
| 机关或职务 | 游戏职责候选 | 约束 |
|---|---|---|
| 中央领导职务/日常执行 | 执行有效路线、组织事务、授权内接触、提出议程 | 无权替代集体决议或作超范围承诺 |
| CAP | 在授权范围内作日常重大政治决定、审议动议、监督执行 | 不将CAP等同大会；不得越权修改高位有效规则 |
| 全国委员会 | 连接省联合会与中央，对实际权限内的重要事务进行集体审议 | 代表身份、权重、召集、决议效力按核定规则；不因名称猜测与CAP固定上下级关系 |
| 全国代表大会 | 讨论路线、通过实际权限内决议、进行组织与领导机关选举 | 政治路线表决与改选是不同程序；不能从动议票直接算CAP席位 |
| 省联合会/支部 | 自主管理地方组织、提出请求及政治意见、按实际规则产生代表和授权 | 中央不直接操控地方支部；不增地图经营或地方资金资源 |
| 众议院党团 | 议会事务与内部团体决定 | 党内路线约束如何传导党团、纪律和投票由D5细化 |
权限查询以实际机关、事项类型、规则适用日期、发起资格、现行授权、程序状态及例外为依据。建议配置事项权限表，不使用一条虚构的“大会>全国委员会>CAP”顺序覆盖全部事项。规则未核时标研究缺口；候选测试可显式采用临时抽象规则，不进入正式历史开局。无需玩家主持每周CAP会议或每季度逐项处理日常事务，月内会议按实际需要及D1检查点聚合；1936手册频率是设计参考，确切1934起始频率待核。只有实际议题和召集资格才生成会议行动；普通例行程序不额外扣行动。

## 4. 决议、授权及冲突
独立记录决议ID、来源机关、事项及版本、表决结果、通过/生效日期、范围、授权对象、允许事项、限制、有效期、修改/废止程序、替代关系及执行记录。明确区分常规职权、特定授权、明确禁止、程序条件与政治承诺。不因没有找到一项专项授权就默认所有行为非法；仅有常规职权或符合实际授权时可执行。例（虚构）：中央可初步接触其他左翼组织，但正式组织协作须由有权机关批准；接触权不自动扩为缔约权；获得授权不保证对方同意。
权限判断：先判断机构/职务的法定能力与程序，再判断具体生效决议及范围；同一事项多个决议按真实替代条款及有权机关关系解释。新决议只在有权变更且明确生效时修改旧决议，不使用“最后写入即胜出”；相互冲突无法解释时进入有权澄清程序，不能执行冲突范围内未经授权行为。决议修改仅影响未来行为，已实际发生政治事实不回滚。外部协议独立记录：党内撤销授权不自动抹消外部已成立义务；D4处理改约、退出和违约后果。UI03-02/B与UI02同源查询；仅展示玩家可知原因，不泄露后台票意。

### 4.1 D3-R03 结构化决议效力与局部冲突处理
决议保留原文与正式版本，同时以经过制度核定的结构化效力条款供权限查询使用；不以自然语言相似度或事项标签直接判定冲突。每个条款至少描述事项域（matter_domain）、具体行为、授权/受约束主体、作用对象与范围、效力类型（授权、禁止、附条件等）、适用条件、生效/失效时点、来源机关与权限依据、替代及例外关系。复合决议可拆成多个关联条款；条款语义未核定时留研究/实现缺口，不能假装文本已自动转换成可靠规则。
冲突判定：先选取在相关时点生效且适用于该行为的条款，检查对象、范围、条件和行为是否真实重叠，再检查明确替代、例外及有权机关的事项权限；仅在无法相容或无法按有效规则消解时登记待澄清记录。相同事项域、范围重叠不充分构成冲突；不同事项域如实际约束同一行为，也须通过明确的关联规则检查，不因分类标签不同跳过。例：允许初步接触与禁止未经授权签署协议可同时成立。禁止以新旧日期或笼统的“禁止优先”替代实际效力判断。
检测器只登记待澄清事项、关联条款、影响行为和可知原因，去重并在实际效力变动后重验；不凭此取得提案权、自动生成正式议程或作出决议。由有资格的主体依真实程序提出澄清，或在已有制度明确允许自动受理时进入议程。澄清前仅限制确实无法确认合法性的具体行为，保留不受影响的明确职权、查阅及合法澄清路径；未决冲突不是全领域锁定或天然必答。对已有外部义务单独校验可履行权限与实际义务，不自动宣布停止履约、免责或协议失效。确有不可错过的期限时依D1处理必答及合法零资源回应。澄清、修订、废止须由有权机关完成，记录生效时点与后续影响，旧记录不被抹去。

### 4.2 D3-R05 组织权限、政治义务与国家制度效力
| 约束类别 | 判定与结果 |
|---|---|
| 组织权限 | 以SFIO名义缔约、动用党资金等须有实际职权或授权；无权不得作为合法组织行动执行 |
| 党内政治义务 | 对具体议员、阁员或代表的政治指令、组织承诺及纪律要求；如实际制度允许发生违背，记录真实行为与相关义务冲突，不强行取消行为 |
| 国家制度效力 | 议会投票、内阁任免等由D5独立按国家制度判定资格、程序及效力，党内不同意不自动使有效选票或合法任免无效 |
发现可能违反党内指令的行为后，保留外部实际事实，核验当事人、当时有效指令、适用范围、例外及其实际效力；若存在违背，可生成有因果关联的政治争议与后续反应。不得检测后自动申斥、除名、分裂或默认列入正式议程。经具备资格的主体提出且有权机关依法受理，才进入纪律程序；可能结果包括不处分、容忍、协调、批评、修订决议或依法处分。具体纪律程序、任免效力、党团/议席归属由史料与D5进一步核定，不把1933年分裂当成自动触发公式。D2硬性制度限制与政治约束分类适用；不能把党内政治指令一律当成国家制度硬锁，也不能将实际具有硬性效力的规则一律降为软约束。

## 5. 动议与会议流程
候选生命周期：议题/请求→提出具体动议版本→受理并确定有权机关和议程→讨论、可行修正或合并（真实权限与程序）→正式表决→结果（通过/否决/合法延期/撤回）→通过且生效才改变授权/路线。未受理请求不等同已列入议程；议题不自动变成动议；延期不是通过。修正案若涉及实质内容，生成新版本、重新检查权限、评估与表决，不沿用旧版支持或批准。已有会议和议程可以处理多个议题，但不得将无关事项打包规避授权及成本。对于确实有权直接采取的行动，不强制人为插入CAP动议。
玩家可对正式程序提出推动原案、修订方案、合法延期、撤回己方动议或回应已提出事项等；不能撤回不属于自己的动议、跳过其他主体同意或直接指定票数。自主主体也可提案、反对、提出条件。会议到期自动进行制度结算，是否需要玩家选择由实际决策权限和截止决定，不将全部投票设成必答弹窗。必须回应时允许零资源合法回应，如不推动额外方案而让既定议事程序继续；不得借免费回应更改授权、替其他主体投票或无限延期。月末普通来函次月处理，硬截止检查点暂停续跑。

## 6. 表决模型（候选）
采用实际代表权单位或少量明确分组的票权集合，不逐个模拟全部党员；CAP票权可按真实席位/委员，代表大会按核实的mandats规则，全国委员会按核实的代表及表决规则；三者不能互换。为降低成本，初版可用有相同身份、政治立场及议题判断的票权分组；各组内部可按已定义的实际分歧、缺席、弃权、纪律及程序约束细分，不凭空增减票权，不预设整派一致。仅当有实际制度依据时采用整组投票或代表授权约束。D2四层决策：内部倾向、已表达意见、正式决定、实际投票独立；席位不是预测票数；前台仅显示已知意见、实际权重与已经发生的表决结果，不显示隐藏精准成功率。
每类表决必须声明表决对象及版本、资格与计票单位、有效/在席/实际投票/赞成反对弃权缺席等口径、法定人数、门槛分母、通过比较方式、平票处理、修正/多案竞争流程。不得将弃权、缺席等自动算反对，也不得将未知数据视为零。技术上保存完整票权守恒，若资格票权=赞成+反对+弃权+缺席+其他有依据的类别，则分项需一致；多案竞争不能机械套用二元表决或自动绝对多数。正式投票规则须独立于图形50%线。
虚构桌面测试：33个合格席位，赞成16、反对12、弃权3、缺席2。若规则是全体合格票权严格过半，则至少17，未通过；若规则是赞反有效票28的严格过半，则至少15，且法定人数等其他条件满足时通过。仅用于测试规则接口，不声称SFIO CAP采用任何一种门槛。1937年转录路线表决5393份含弃权；不要与另项参政表决拼成同一事项，也不把5393当人头数或可换算席位。
投票结果按D2稳定事务ID及实际信息截面结算，可复现，重复打开、恢复结算不重投；若制度允许重新表决，必须新程序及新记录。表决反映该时点的具体议题及真实授权，不能因一次通过自动提高所有后续动议的支持。

### 6.1 D3-R02 多案表决与有限综合动议
多案竞争须有按事项与实际制度选定的结算规则。预留两个候选模式接口，不作为已核实的SFIO通用历史程序：A 单轮相对多数，按有效票、资格、法定人数及平票规则确定结果；B 规定通过门槛，首轮无案达标时按适用制度安排复投、决选、合流窗口或形成未通过结果。不得默认有第二轮或强制某案胜出；若规则未核，只能以明确标识的抽象规则做测试。多案竞争声明计票单位、每一票权可选择的项数、分母、弃权/缺席/无效票、平票及收束规则；票权守恒按对应程序口径检验，不能对允许多选的程序套用单选票守恒式。
综合动议是政治协商，不是独立表决模式；可以在正式表决前或制度允许的轮次间发生。由有权主体提出撤回、合并、修订等有效程序，形成新的实质版本并保留原案及原表决记录；不能将旧票数直接相加或静默迁移。对新版本按D2重新评估政治意见，并按第6.2节代表实际授权范围判断可否改投、是否需要新授权及其他合法处置。已取得的程序性支持不等于新案通过。沿D2有限结构化条款、版本去重、轮次/有效变体空间与截止检查点，依法收束；不通过反复合并、拆分或重新启动规避大会期限。若无可达成方案，记录实际未通过/未决结果，依现行制度处理原决议是否继续有效。决议委员会（Commission des résolutions）、合流及综合动议（motion de synthèse）的历史适用范围与具体权限尚未核证，只预留接口，不增设独立管理模块。

### 6.2 D3-R04 代表授权范围与裁量
票权分组可关联由有权组织实际形成的代表授权记录：授权主体、代表/代表团、适用会议和事项、动议版本、授权条款、有效期间、变更/重新授权程序与约束性质。候选范围包括明确指令、附条件授权、有限裁量、自主裁量；不是强制每名代表拥有四种等级，也不是把事前与临场机械划分成两类。对原案的指令不自动覆盖新综合动议；若变更在授权明确允许的范围内，可依实际裁量重新评估；超出范围时按实际程序重新授权、合法拒绝或其他适用处置。不得因中央临场行动直接改写地方授权。
区分硬性表决资格/票权约束与可违反但可能产生政治责任的组织指令：前者按实际制度限制有效投票；后者允许实际行为与指令不一致，并按第4.2节及真实纪律程序处理。没有核实规则时不得预设所有地方联合会均实行mandat impératif或均可自由改投。具体指令制度、变更及违背后果保留H-08/H-09、M-08/M-11/M-13待核；不另设代表游说点数或逐人管理。

### 6.3 D3-R06 代表资格与票权截面
每次正式表决建立可追溯的资格截面：会议与表决ID、适用规则版本、资格确认时点、合格成员/代表及所属组织、票权单位和权重、相关授权版本与实际出席记录。资格和票权应依据适用制度确定，不随实时党员数、派系变化或后台组织规模自动漂移；出席、弃权及实际投票按该轮程序单独记录，不预先固定投票意向。依法确认的资格或授权变更在对应程序允许的时点生成新截面/关联变更记录，不覆盖已完成表决；后续轮次按适用规则延续或更新资格，不必强制每轮重新计算，也不要求整场大会无条件使用同一分母。席位、代表权及授权独立，投票中不重复计算同一票权。未核实历史资格截止、改授权及计票规则时只能使用标注的测试假设；不能用临时扩员或组织拆分增加已经确认的本轮票权。恢复检查点须使用原表决ID及已确认截面，避免重新抽票或重复结算。

## 7. 全国大会和改选
筹备：按实际召集资格确定会议及议程，地方联合会经其真实程序形成代表资格/授权及意见；普通政治分歧可尚未形成提案。代表权由有依据的日期与统计口径生成；暂不确定以党员、缴费、会籍或其他单位折算。会议进行：对有效动议版本辩论、修正、按制度表决；有实质选择才要求玩家干预，正常流程无需逐步消耗行动。会议闭幕：记录各项决议、实际生效及独立的改选结果。CAP改选必须有自己的候选名单、资格、票权、席位数、分配办法及结果；历史33席仅样本，不采用未经核验的比例分配、最大余数或自动多数派改组算法。领导任免、授权生效分别在实际程序完成时更新，不能让历史会议日期或路线结果自动更换本局领导。
D1检查点允许一次大会在一个月内按顺序完成多个程序，不需要每日预算；也允许真实跨月阶段。实际未确定会议日期不显示倒计时。历史会议可作情境和校准锚点；本局是否召开、议题、结果按制度和局势决定，不能强迫重演历史路线。代表大会详情使用已归档UI03-05/A，CAP构成从独立改选记录读取。大会动议的撤回、合流与复投采用第6.1节实际适用的程序，代表资格、票权及授权按第6.2–6.3节记录；改选仍是独立的选举程序，不将综合动议胜出自动换成CAP席位。

## 8. 派系与地方组织
派系是可变政治组织及联盟，不是固定左中右标签。保留政治主张、相关议题、主要代表、真实成员/票权关系和组织行为；政治立场可以重叠，不将每名党员机械归到唯一派系，不重复计算同一制度票权。多数派从某一实际表决/组织联盟形成，不能作为永远固定的正式团体或玩家专属势力。未参与CAP的派系仍可存在并通过实际程序表达意见。
派系变化优先由具体事实触发：持续实质分歧、组织活动、动议竞争、代表或成员变化、联盟形成、退出或纪律程序。单次投票失败或隐藏满意度到阈值不自动产生分裂；不规定每月必须发生动态。合并、分裂、退出、纪律处理需明确行为主体、组织基础、实际程序及成员/席位归属变化，保留原有历史记录；不能由中央点击按钮直接删除派系。具体纪律权限、退出后席位、资产及党团归属待历史与D5核定。
地方联合会按D2有限主体模型，具实际组织基础、社会环境、地方政治意见、报告及请求；重要组织按需单独模拟，其余可聚合。中央组织项目、宣传、接触与授权在真实范围影响地方行为，但不能直接决定地方政治立场或代表票；地方自发活动不扣玩家2次行动。地方报告是所知信息而非实时后台真值；地方联合会、支部数、党员数、代表票、实际党费和活动不是同一指标。初版不增加地图经营、逐支部操作、地方拨款或额外资源；所有中央支出复用D1账目。组织规模及党费收入的转化参数由D7/D8核定。

## 9. 行动预算与情境走查（虚构）
原则：主动提出新政治议程、专门争取支持、请求额外会议、改变路线或进行新实质干预可有主动行动成本；正常受理、既有议程投票结算、发布已生效决议、普通查阅、授权内的例行执行不按步骤收费；具体主动执行或外交接触仍可能消耗行动。不得把整个议题一律打包免费，亦不得为每次查看、选择、确认、表决等技术步骤收费。M-09仍需实际成本校准。
测试候选：当月2次，使用1次推动一项明确的授权动议（仅测试价格），正常受理、修订的程序性处理、表决结算不额外扣次；通过后仍有1次可用于独立的实质对外接触（仅测试价格），不因翻看授权或等待回应再扣；未通过则根据实际情况保留剩余1次用于其他合法行动或不行动，不能自动获授权。新的实质修订、额外会谈或拉拢行为是否构成新干预，按规则处理，避免免费无限循环。若政治截止发生在月末且额度用完，至少存在不消耗资源的合法程序回应，不承诺玩家可实现偏好结果。D4–D6结合实际选举和联盟验证两次行动预算，不冻结示例价格。
另一测试：玩家推动参政路线遭CAP否决→继续行使既有合法职权→代表大会依程序形成新路线并独立改选→新中央领导层继任，玩家视角继续，现行决议及外部协议分别按效力处理；不能通过改选刷新行动预算或使党资金恢复。
