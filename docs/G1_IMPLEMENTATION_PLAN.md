## 1. 技术选型与交付边界（G1-01）
推荐TypeScript严格模式、React组件、原生CSS、Node.js 24 LTS、Vite、npm锁文件、Vitest无DOM规则测试、Playwright真实浏览器测试。引擎无React、DOM、网络、系统时钟及随机全局依赖；不引入运行时LLM、后台数据库、服务器、重型事件溯源或全局状态框架。先以单进程同步事务推进；性能测量需要时才引入Web Worker，不改变接口。官方参考：[Node.js LTS](https://nodejs.org/en/about/previous-releases)、[Vite构建](https://vite.dev/guide/build)、[Vitest](https://vitest.dev/guide/)、[Playwright浏览器](https://playwright.dev/docs/browsers)、[MDN本地存储](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)（2026-11-27核对）。具体相容版本及依赖锁定在G1技术确认后的实际工具链验证，不猜测当前小版本。软件及素材许可证另登记，不直接复制受限字体/史料插画。
开发/CI使用本地开发服务器或静态测试服务器；玩家交付优先提供无需安装、无需服务器、无需网络即可直接打开的HTML。Vite默认静态构建并不保证file://可用，单文件交付需专门内联/打包脚本、资源与配置内嵌、无运行时fetch/CDN及外部字体、无不可用动态模块加载；另保留标准静态构建供托管。先验证最小构建产物在桌面Chrome/Edge的file://与断网条件、导入导出和刷新；Firefox作为补充兼容目标，实际测试范围确认后登记。localStorage在file://行为不保证，浏览器自动存档仅尽力而为并显示失败；手动版本化JSON导出/导入是必要路径，不依赖存储权限或固定文件路径。G1当前未做实际构建、安装、CI或浏览器测试。
 
### 1.1 G1-R01 双构建、离线脚本及字体
开发及标准静态托管使用正常ES Module构建；离线单文件单独构建为一个HTML，内联经典非模块IIFE脚本、CSS、必要配置与合法资源，不保留模块导入、动态分块加载、运行时fetch、CDN或外部字体依赖。不以所有内联ES Module必然失败为前提，选择经典脚本是为减少file://的跨资源加载限制。打包器须正确处理脚本/样式内联的HTML终止字符与编码，不靠简单拼接破坏资源；G2-A确定实际实现并验证产物，不在此冻结插件或小版本。
HTML语言设为zh-CN，主中文公文风格使用系统字体回退栈：`"Songti SC", "SimSun", "STSong", "Noto Serif CJK SC", serif`；表格数字等沿既有UI规范。系统字体随平台与安装情况变化，不承诺跨平台像素一致，不内嵌未经授权字体或默认完整CJK字体。实际缺字/观感问题通过浏览器与系统验证，必要时另审合法字体子集及包体积；不因此修改58图基准。
G2-A用实际最小试验页面验证标准构建及离线HTML；桌面Chromium环境通过file://加载、断网、基本交互、刷新及不依赖localStorage的测试存档文本导入导出，记录浏览器、OS、版本、控制台错误和网络请求（不得依赖外部加载）。G2-B以后以真实游戏存档与政治行为复验；试验页面不是可玩游戏。Chrome/Edge为主要目标，Firefox补充；无法实际测试的环境明列NOT_RUN/BLOCKED，不以Chromium测试代称所有浏览器通过。具体工具链、实际运行和字体效果均待G2-A验证。

### 3.1 G1-R02 常驻投影与按需查询
PlayerView仍为D2/D85统一可见性边界，不再要求单个全量对象。公开会话接口的概念方法为getSnapshot(): SessionSnapshot、queryArchive(filter/page)、queryDetail(publicId)、previewQuote(draft)、dispatch(command)、importSave(rawText)、exportSave()；实际类型及同步/异步签名随G2-A工具链验证确定，不扩张玩家权限。SessionSnapshot只包含顶底栏、真实必答阻断、共享工作/简报计数及必要轻量摘要；每次已提交命令/检查点或成功导入后按同一已提交截面更新，若可见内容未变则不暴露内部状态变化。当前页面摘要、档案检索、政治详情、列表、分页及费用预览按需查询，不每次构造所有页面。
全部查询零政治副作用，不修改WorldState、不生成政治事实、不消耗随机抽样、不提前锁定成本；纯缓存为可丢弃实现细节。搜索、过滤、排序、分页总量、禁用原因、错误及关联入口在引擎可见性层内完成；公共ID、版本、缓存失效与更新通知不泄露隐藏对象或内部revision。查询需基于一致的已提交状态；跨命令更新时允许刷新当前查询，不能拼合旧权限和新数据。UI独立保留筛选、滚动位置、弹窗栈与导航，不因命令提交重置，合法对象消失/权限变化时按真实可知原因收束。报价预览仅基于可知信息，实际提交独立重验；如无安全具体原因则给合法通用反馈。G2-B起验证常驻与按需数据一致、查询无副作用、配对非干扰和局部界面状态；性能优化基于测量，不引入第二套权威状态。

### 3.2 G1-R03 版本化键控确定性随机
禁止全引擎共用按访问顺序推进的随机游标作为政治随机来源。合法且实际需要的不确定选择通过稳定语义键派生：算法/编码版本、本局种子、领域标识、稳定政治事务或检查点ID、抽样用途、稳定对象ID及必要的局部抽样序号。明确区分不同用途、候选对象、轮次与真实新事务；同一键及算法版本可复现。同一检查点内多个选区/主体或多次抽样使用独立语义键，不能以候选列表遍历下标、全局递增事务计数、UI点击顺序或玩家requestId冒充稳定抽样标识。业务ID由稳定语义或可追溯因果标识产生；真实新政治机会可生成新键，取消/重试、重复请求、读档、预览或无实质变化的同一事务不应获得重抽。若政治条件、候选集合或真实因果变化，实际结果可以合法改变；随机隔离不要求不同世界的政治结果恒定。
G2-A确定跨平台可复现的具体算法、无歧义规范化键编码（含类型/长度边界）、输出范围、分布/整数映射及固定测试向量；不得依赖Math.random、系统时钟、平台不稳定哈希或全局游标。若需多次内部采样/拒绝采样，使用该语义键内独立且明确的局部序号，不影响其他事务；避免取模偏差及未限定的重抽。已发生的政治结果及必要抽样记录/键随事务保存，保存算法版本及种子、必要的局部记录而非单一全局随机游标；不兼容版本明确迁移或拒绝，不重算已发生历史。G2-A单独建立固定向量与键隔离试验；G2-B/D及后续模块复验插入无关抽样、改变遍历顺序、重复提交、保存恢复和故障回滚不扰动已有语义抽样；正常查询不得调用政治抽样接口。F1基准无随机的既有假设保持，随机验证用独立工程夹具，不改成所有政治判断随机化。

## 4. 执行与保存（G1-04）
一次命令事务：读取当前实际状态→检查请求ID及规范化请求内容→验证配置、身份、权限、时点、版本、报价、资源和重复条件→计算确定性后续事实与账目变更→不变量校验→原子提交新状态、已处理记录与实际费用→投影允许公开的反馈。技术失败不提交半状态；政治拒绝是实际结果，已付接触费不回滚。同ID同请求返回原可知结果并结合当前可见性，不重执行；同ID不同内容明确拒绝，不用该机制自动重试新政治行动。若恢复前请求已提交则通过持久化ID识别，未提交保持旧状态；内部错误只进入独立诊断。
当月可用AP=2−spent−reserved；账面=期初+实际收入−支出；可用=账面−有效预留−未重复计入预留的受限金额。预留转支付同事务减账面及对应预留；不可撤销未付义务不是预留或负现金；同点无合法分配规则保留受限金额及缺口，零资源接受真实后果。D84优先规则不可被页面顺序覆盖。
时间推进以D1/D83/D84为约束，以下是F1默认同点顺序而非史实。较早真实时点先行，依赖优先；同点先依法确认已到达收入与已有到期约束，再处理有合法条件的不可撤销付款、可调整项目支付和下一期预留，随后普通开放决策；不能跨过更早硬期限。普通月末推进无日期预约/项目启动及自主行为；有真实日期的先处理，结算事实与后续报告按因果。暂停只在真正必须回应且下一窗口会错过期限时发生，保存cursor；已有事实不重算。D83次轮前置/选举例外在G4接入真实选举，G2仅验证通用检查点与预算契约。无依赖自主意向从同一信息截面形成；有依赖按拓扑处理；同级无合法分配不得按ID挑赢家。独立无冲突任务可用稳定键排列以实现复现，但不得借排序改变政治权限、支付分配或可知信息。环/不可解释冲突为配置缺陷。每次触发生成稳定因果ID，有限变体/期限阻止无限反应；超出计算保护阈值报告技术缺陷而非吞掉义务。末月封存不发61月额度；实际组织消失兜底在G3–G5接入，F1只验证终止接口。
存档信封：formatVersion、rulesVersion、configId/hash、runId、完整内部快照、seed、键控随机算法/编码版本及必要局部抽样记录、cursor、已处理命令与检查点、账目/预留、事实/披露、完整性校验；校验失败或版本不兼容时拒绝/明确迁移，保持当前有效存档。完整文件通过独立适配器导入导出，不作为玩家档案查询；校验和仅检测意外损坏，非防作弊。候选采用每次成功命令及暂停/封存后生成一致快照，双槽或等价安全替换保存最近有效副本，保存失败提示并允许导出；不声称浏览器存储事务在所有环境可靠。导入前验证ID、引用、单位、安全整数、预算与余额、检查点和版本，不接受半成品或重算政治历史。
 
### 4.1 G1-R04 持久化请求幂等及不透明存档
每局内部保存轻量processedCommands映射（概念形态Record<requestId, ProcessedCommand>，实现使用安全键容器及严格ID校验）；记录canonicalHash或规范化请求内容、可验证内容一致性、outcomeRef、recordedAt/committedAt及status（committed或rejected）。同ID同规范化业务请求返回已记录的允许公开结果，不再次执行；同ID异内容拒绝，不覆盖原记录。规范化排除纯传输元数据，保留实际身份/目标/版本、报价及业务条件，明确编码、相等判定和摘要碰撞处理；不能只用不可靠短哈希判定相等。requestId是传输幂等标识，不是政治随机键或新政治机会。结果引用稳定存在，不在60月局内任意淘汰仍可重放的记录。UI重复点击及重试应复用同一请求ID。
已执行接触遭政治拒绝属于committed，费用与实际事实保留；通过格式/身份边界且具有合法请求ID的确定性业务校验拒绝记录为rejected（只记录请求处置，不制造政治事实/费用），以后条件改变应使用新的合法请求。无效/未解析请求、ID格式错误及不属于当前会话的请求不污染已处理记录；同ID冲突不替换原记录。未提交的技术异常不留下伪成功、半笔费用、半个事实或永久业务拒绝，允许对同一请求安全重试；若事务已提交但反馈/保存失败，保留实际已提交状态、以原ID查询，提示保存状态，不能将政治行为撤回或再次执行。命令结果、记录与实际状态原子提交，持久化快照包含同一截面的已处理记录；校验/读档时核验引用、状态和一致性。旧结果回传按当前D2可见性，不直接序列化内部outcomeRef/诊断或借命令映射泄露。幂等不等同于本地防作弊，也不保证未成功持久化的会话可以跨进程恢复。
UI导入仅允许读取文件文本并作为不透明string交给sessionAdapter.importSave(rawText)，可检查大小、读文件失败等非政治元数据，不解析、预检、修改或打印完整存档JSON/WorldState。导出由会话适配器生成不透明文本，UI只负责交付文件；政治档案仍从PlayerView查询。解析、格式/大小/深度及安全值校验、版本/引用/不变量检查、完整性校验和迁移在引擎持久化边界内完成；成功才原子替换会话，失败保留旧会话，只返回可知安全错误。测试UI无内部存档解析路径、损坏/不兼容导入、重复命令、拒绝与技术故障、提交后反馈失败及恢复一致性。G2-A先验证独立存档文本交付试验，真实游戏幂等与恢复在G2-B起接入。
