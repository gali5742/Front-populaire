## 3. D1：核心回合候选规则
### 3.1 时间及检查点
月份是玩家唯一常规行动预算周期，不设每日行动资源。月内具有顺序的政治程序可设置检查点；历史日期仅在有依据或规则确需截止时使用，不假装每次行动都有一个真实日历日。普通查阅、即时行动不自动耗费一天。各检查点有稳定标识、所属月份、截止条件、依赖、是否阻断、状态及完成记录；同一检查点仅结算一次。
建议阶段：月初进入（重置当月行动额度、处理到期的月初事项、更新可见信息与简报）→开放决策（行动即时或安排，响应可在行动后产生）→请求结束（检查当前到期必答）→按依赖和到期顺序处理月底事项→最终检查并封存本月→下一月。月初尚未完成的必答应进入当月开放决策，不因生成简报而被视为完成。具体收入、费用、主体和经济钩子的内部先后仍需校准；禁止以页面顺序决定结算。
当月底处理中产生必须在当月解决的事项，暂停在当前检查点；月末已完成的结果保持，不重复结算。建议返回受限决策态：可查阅、回应本检查点、撤销尚未开始且允许撤销的安排；不重新打开已失效机会，不补发行动额度。回应可以使用当月尚余资源的可选方案或零资源合理回应。待全部到期阻断解决，再继续剩余检查点。若需要在暂停时新增普通行动，须明确其截止时序及许可，当前默认不开放；D6选举专属窄例外见下文，已按D83原则通过。若事项仅在次月到期，则允许跨月保留待回应，但不得跨过其真实截止检查点；已确认的本月必答一律不能提前结束。每个事件只能在一个明确的当前检查点阻断，不能无限重复产生同一回应要求。
**v0.2调度补丁（原则通过，参数待验证）**：月底结算中生成的常规非玩家提案及衍生事务，默认排入次月正常决策窗口。实际发生的行为、结果及其披露仍按真实时点记录，不为避免弹窗而改写事件日期；未公开信息不提前披露。只有直接跨入下一可用决策窗口将错过必须由玩家回应的真实截止或程序节点，才可暂停月底结算（如即将截止的退选决定或需及时回应的政府危机）；危机的名称、严重性或NPC提出请求本身均不自动构成阻断。玩家主动行动当下产生的正常反馈不因此延后；已经进入当前检查点的正式义务不得强行移至次月。检查次月行动开放前的真实期限，不以月份作为唯一判断依据；最后一个月的普通待续事务按M-07结局规则处理，不创建第61月。
1936首轮/次轮跨月仅是边界测试：必须在次轮结算前安排协商截止检查点，不能通过直接结束月绕过；哪一月行动额度支付哪类协商、全国协议与逐选区粒度由D6决定。最后一个月结束后不再发放第61月行动额度；超出游戏时限的事项如何进入结局留M-07，不能继续收取未发生月份的例行费用。

**D6配套时序补丁（D83原则通过，运行验证待完成；不改变D79既有原则）**：详见[D6 §7.1–7.3](MECHANISM_D6_DRAFT.md)。实际时点、截止及依赖确定顺序，明确月内检查点及其必要依赖先于会跨过该点的无日期月末批处理；较早真实安排照常执行，同点规则与不可行依赖待校准。首轮结算产生且仍合法开放的选举事务，若下一正常窗口将错过真实期限，可在月底受限态提供与该检查点直接相关的有限实质政治干预，使用该月尚未消耗/预留或合法释放的原有行动与资金；不恢复一般行动目录、不补发或跨月借用额度。只有未开始且允许撤销的预约可释放可撤销预留；已执行成本与义务不回滚。保持合法零资源回应及正常自主程序，不为全部地方争议设置必答。首轮所在月月初简报提示可能的限时协商及原月额度约束，不强制锁定行动。
跨月时若存在早于正常开放窗口的次轮前真实程序，合法进入新月后只发正常额度一次，依实际到期事项和依赖处理月初事务，先开放与当前时间及权限兼容的前置检查点（含实际同期其他政治事务）；未来结果依赖事项不得提前执行。推进动作指向实际检查点（例如结算第二轮）而非直接封存新月；完成后以本月剩余额度和实际账目进入正常开放决策。存档恢复保留阶段、游标及结算ID，不重复发点或扣费。此窄例外和前置状态已按D83原则通过；仍需D8压力测试，不扩张为所有月底事件都可新增主动行动的通用规则。无真实窗口则不强制出现子阶段。

### 3.2 行动与结果生命周期
| 状态/路径 | 资源处理候选 | 规则 |
|---|---|---|
| 仅打开、选择、返回 | 无 | 未确认不建立政治事实；可保留临时选择 |
| 即时行动提交 | 同一次有效提交扣实际成本 | 校验权限、期限、对象、额度、资金及重复规则 |
| 已安排（未执行） | 预留行动机会及约定资金 | 不提前记成果；显示预计执行时点 |
| 执行前条件失效或允许撤销 | 释放尚未执行的预留 | 记录原因，不自动改选；过月额度不结转 |
| 执行开始 | 将本次预留转为实际消耗 | 原子结算，不再重复扣款；尚未发出的行动与已发出但被拒绝区分 |
| 等待对方回应 | 已执行的接触不退费 | 单独记录磋商/工作状态、下一时点及实际政治回应 |
| 完成、拒绝、部分成果或到期 | 按实际发生的成本与结果记录 | 不自动退回真实已发生消耗；拒绝不等于未执行 |

同一个操作标识只能产生一笔对应的费用及一个提交结果；技术失败不能留下半笔扣费或半个政治后果。重新打开详情、重复点击、读档继续和恢复结算都不得再次执行。政治条件由主体、议题、权限/授权、协议、时序、可用资源共同决定，而不是机构按钮写死的解锁链；提交与预约执行前均重验。公开原因必须来自玩家可知信息，不能泄露隐含立场。规则可明确何时可重试，不设所有行动统一冷却。安排默认当月执行；跨月等待表示已发出行动后的后续结果，而非无期限携带当月行动预留。确需未来行动，未来费用和条件需单独规定。

### 3.3 统一账目
候选口径：当月剩余主动行动=2−当月已消耗−当月仍预留，范围0至2；未使用机会不结转（新增建议，待确认）。资金账面余额=期初余额+已入账收入−已入账支出；预留=未支付且仍有效的经费承诺；可用党资金=账面余额−预留。预留不等于实际支付；预测不等于预留。不得以负可用资金启动新行动；不静默透支。预留转支付时余额和预留同时减相同金额，避免重复占用；已支付不可因取消后续工作退款，确有退款的另记真实返还流水。只有取消或未开始而失效释放未用预留。成本如变化须按明确的允许范围或重新确认，不能自动超额。例行费用与既有义务如遇资金不足，记录未支付义务与处置，不凭空入账或自动变成债务资源；财政困难后果由机制另定。
例：虚构测试余额10,000法郎、2次行动；安排A预留1次和3,000法郎后剩余1次、账面10,000、可用7,000；执行A后剩余仍1次、账面及可用均7,000；执行前取消则恢复2次和10,000。纯查阅不改变政治状态；不干预仍可能产生来自其他主体或外部环境的有利或不利结果，但不凭空获得未执行的主动行动效果。党资金、国家财政、党员、席位分开。UI01/02/03-06读取同一账目和项目记录，明细不直接编辑。

**D7 v0.2配套支付规则（D84原则通过，实际验收待完成；不改变D79/D83已确认预算边界）**：见[D7 §6.1](MECHANISM_D7_DRAFT.md)。按实际时点、既有有效优先规则、不可撤销到期义务及付款条件处理；在其后处理仍可合法调整的日常/项目支出，再核验未来滚动预留及新安排。核心运转或长期工作标签不自动改写既有义务；已付不回滚。对同一检查点同一资金池的同级竞争，若无合法确定分配/部分付款规则，则不按列表、ID、随机数或默认平分挑选支付对象，创建共享经费短缺处置记录。保持无争议且有独立资金保障的合法付款；争议未分配资金不挪作低优先新安排。受限部分使用同一党账既有预留/未分配金额表达，实际资金不重复占用、不虚构足额预留或负可用余额；未保障金额独立记录。具体合法约束、优先及部分付款参数仍待D8。
零资源默认可接受真实未付及其后果，未付到期义务不免除，未发生计划不变债务；需经费却未获合法付款的工作不获得付费执行进展，已完成成果保留。按已有权限提供缩减/暂停、明确分配或接受未付等合法处置，不要求额外行动或党资金才能继续月份；实质变更、外部协商仍按D1收费，不因处置免费解除义务。仅真实必答期限暂停，其他情况按实际条件记录并继续；跨月重新核验真实余额和义务，不重复结算、不把未付视为合法延期，仍受约束的资金不得转入新低优先安排。恢复依据冲突/交易ID，UI01/02/03-06同源显示缺口与处置。D7组织收入仍是候选，非正式历史党费参数。

### 3.4 必答事件与可选机会
事件由实际政治情境、其他主体行为或明确制度期限产生，不把历史索引当作固定任务脚本。候选类型：可选机会（可忽略、到期失效）；需正式回应（到截止检查点未回应则阻断）；纯信息/结果（只读、不阻断）。等待其他主体的答复本身不自动成为玩家必答。关闭、查阅、未确认选择不改变事件处置状态。必答在任何合法资源状态下至少一项政治上合理、可提交且不消耗主动行动和党资金的回应；零成本回应可以产生真实政治后果，不要求优于其他方案。必要时使用拒绝、明确维持现状或合法延期；延期需实际程序允许，不能借同一事件无限推迟。不能通过技术性权限门槛让所有选项锁死。需正式回应与纯不干预不同，实际选项成本须说明。多项必答逐项记录、任意合法顺序处理，依赖关系显式；解决一个不清除其他阻断。已处理事件历史回顾只读。
若事件规则无法构成合法零资源回应，视为设计错误，不能给玩家悄悄自动选择、发放额外行动或假装已解决。实现验收须覆盖资金为零、行动为零、授权不足、多个同时到期及月底途中产生必答。历史触发时点与本局实际前提分开记录；具体历史事件、触发概率仍待设计。

### 3.5 长期工作默认候选（M-06/M-14）
建议统一普通长期工作：当月确认安排并预留启动行动及首期资金，月末校验并启动，次月为首个执行月；次月月初支付首期及其后每个执行月的当期费用，月底登记实际进展。若特定工作确需即时启动，作为明确规则例外，单独给出当月支付和起算，不能由UI文字临时决定。仅预留已承诺的最近一期及实际固定启动费（如有），不预留全部未来预测费用；首次预留资金转支付不二次占用。启动时扣除安排的行动成本；启动前撤销释放预留；未能启动则保留失败原因并释放尚未发生消耗。具体月费、启动费和行动成本不在此冻结。
例：1月安排一个3个月有限期项目，2月–4月为实际执行窗口；首期预留1月建立，2月初支付、2月底登记第1个已执行月。预测总成本仅按已知方案和计划估算。项目若资金不足，建议进入“待经费处理/暂停”而非自动获得效果或形成负余额；未付当期不计付费执行进展，已经发生的义务单独记录，通知玩家并提供缩减、终止或其他实际可行路径。是否自动恢复、暂停能否延长计划结束日、合同义务及失败影响待定；暂停期间不自动重置既有成果。变更/终止默认从下一执行月起生效（候选），仅未支付且尚可取消的预留释放；真实已投入费用不返还，调整是否消耗行动及具体政治代价待确认。持续活动没有虚构完成百分比；谈判记录的是往来、条件及等待，不默认视为持续付费项目。仅当实际存在费用或工作责任时使用对应项目规则。
**v0.2可调整滚动预留补丁（原则通过，参数待验证）**：当期支付后，若项目尚有下一实际执行期且已有有效安排，则在开放当月普通决策前建立下一期经费预留。最后一期支付后不再预留不存在的下一期。计划性支出与已有约束力的付款义务分别记录；项目允许缩减或终止时，在合法生效且确认变更后释放或调减尚可撤销的预留，不取消不可撤销的付款义务，不返还已支出款项，也不默认变更免费。若有资金缺口，记录真实可预留金额及未保障部分，不虚构足额预留、负可用余额或已支付费用；多个项目争用资金、日常开支与既有义务按§3.3 D7配套规则（D84）处理，具体优先/部分分配参数仍待M-06/M-14及D8核定，禁止临时按列表顺序分配。单项目示例：当期付款后余额20,000、下期计划费用5,000，则足额预留后可用15,000；若合法终止且无该期付款义务，则释放5,000；余额仅3,000时须展示实际可用与未保障的金额，不能声称已足额预留；竞争资金按§3.3 D84原则处置，具体部分预留规则待定。下期预留转支付仍仅扣款一次。

### 3.6 政治程序与主动行动成本边界（v0.2原则通过）
区分主动政治干预、已有授权下的执行、正常制度程序推进、对既有事务的回应和普通查阅。不得因为一个政治程序由多个技术步骤、弹窗或数据状态组成，就逐步自动扣一次行动。也不因步骤属于同一议题，就把一切主动干预打包免费；实质新增政治投入、改变授权或另行启动磋商，仍需依据具体规则判定成本。既有授权不能替代对方同意或法定程序。D3–D6须明确每条关键流程的付费节点、零成本程序节点及真正政治选择，用每月2次、总60个月的预算做情境走查；不能把省操作步骤等同为省略制度。具体行动价目仍待核定。
