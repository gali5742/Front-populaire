## 3. D1：核心回合候选规则
### 3.1 时间及检查点
月份是玩家唯一常规行动预算周期，不设每日行动资源。月内具有顺序的政治程序可设置检查点；历史日期仅在有依据或规则确需截止时使用，不假装每次行动都有一个真实日历日。普通查阅、即时行动不自动耗费一天。各检查点有稳定标识、所属月份、截止条件、依赖、是否阻断、状态及完成记录；同一检查点仅结算一次。
建议阶段：月初进入（重置当月行动额度、处理到期的月初事项、更新可见信息与简报）→开放决策（行动即时或安排，响应可在行动后产生）→请求结束（检查当前到期必答）→按依赖和到期顺序处理月底事项→最终检查并封存本月→下一月。月初尚未完成的必答应进入当月开放决策，不因生成简报而被视为完成。具体收入、费用、主体和经济钩子的内部先后仍需校准；禁止以页面顺序决定结算。
当月底处理中产生必须在当月解决的事项，暂停在当前检查点；月末已完成的结果保持，不重复结算。建议返回受限决策态：可查阅、回应本检查点、撤销尚未开始且允许撤销的安排；不重新打开已失效机会，不补发行动额度。回应可以使用当月尚余资源的可选方案或零资源合理回应。待全部到期阻断解决，再继续剩余检查点。若需要在暂停时新增普通行动，须明确其截止时序及许可，当前默认不开放，待D6压力测试复核。若事项仅在次月到期，则允许跨月保留待回应，但不得跨过其真实截止检查点；已确认的本月必答一律不能提前结束。每个事件只能在一个明确的当前检查点阻断，不能无限重复产生同一回应要求。
1936首轮/次轮跨月仅是边界测试：必须在次轮结算前安排协商截止检查点，不能通过直接结束月绕过；哪一月行动额度支付哪类协商、全国协议与逐选区粒度由D6决定。最后一个月结束后不再发放第61月行动额度；超出游戏时限的事项如何进入结局留M-07，不能继续收取未发生月份的例行费用。

### 3.2 行动与结果生命周期
| 状态/路径 | 资源处理候选 | 规则 |
|---|---|---|
| 仅打开、选择、返回 | 无 | 未确认不建立政治事实；可保留临时选择 |
| 即时行动提交 | 同一次有效提交扣实际成本 | 校验权限、期限、对象、额度、资金及重复规则 |
| 已安排（未执行） | 预留行动机会及约定资金 | 不提前记成果；显示预计执行时点 |
| 执行前条件失效或允许撤销 | 释放尚未执行的预留 | 记录原因，不自动改选；过月额度不结转 |
| 执行开始 | 将本次预留转为实际消耗 | 原子结算，不再重复扣款；尚未发出的行动与已发出但被拒绝区分 |
| 等待对方回应 | 已执行的接触不退费 | 单独记录磋商/工作状态、下一时点及实际政治回应 |
| 完成、拒绝、部分成果或到期 | 按实际发生的成本与结果记录 | 不自动退回真实已发生消耗；拒绝不等于未执行 |

同一个操作标识只能产生一笔对应的费用及一个提交结果；技术失败不能留下半笔扣费或半个政治后果。重新打开详情、重复点击、读档继续和恢复结算都不得再次执行。政治条件由主体、议题、权限/授权、协议、时序、可用资源共同决定，而不是机构按钮写死的解锁链；提交与预约执行前均重验。公开原因必须来自玩家可知信息，不能泄露隐含立场。规则可明确何时可重试，不设所有行动统一冷却。安排默认当月执行；跨月等待表示已发出行动后的后续结果，而非无期限携带当月行动预留。确需未来行动，未来费用和条件需单独规定。

### 3.3 统一账目
候选口径：当月剩余主动行动=2−当月已消耗−当月仍预留，范围0至2；未使用机会不结转（新增建议，待确认）。资金账面余额=期初余额+已入账收入−已入账支出；预留=未支付且仍有效的经费承诺；可用党资金=账面余额−预留。预留不等于实际支付；预测不等于预留。不得以负可用资金启动新行动；不静默透支。预留转支付时余额和预留同时减相同金额，避免重复占用；已支付不可因取消后续工作退款，确有退款的另记真实返还流水。只有取消或未开始而失效释放未用预留。成本如变化须按明确的允许范围或重新确认，不能自动超额。例行费用与既有义务如遇资金不足，记录未支付义务与处置，不凭空入账或自动变成债务资源；财政困难后果由机制另定。
例：虚构测试余额10,000法郎、2次行动；安排A预留1次和3,000法郎后剩余1次、账面10,000、可用7,000；执行A后剩余仍1次、账面及可用均7,000；执行前取消则恢复2次和10,000。无资源的纯查阅或不干预不产生政治收益。党资金、国家财政、党员、席位分开。UI01/02/03-06读取同一账目和项目记录，明细不直接编辑。

### 3.4 必答事件与可选机会
事件由实际政治情境、其他主体行为或明确制度期限产生，不把历史索引当作固定任务脚本。候选类型：可选机会（可忽略、到期失效）；需正式回应（到截止检查点未回应则阻断）；纯信息/结果（只读、不阻断）。等待其他主体的答复本身不自动成为玩家必答。关闭、查阅、未确认选择不改变事件处置状态。必答在任何合法资源状态下至少一项政治上合理、可提交且不消耗主动行动和党资金的回应；零成本回应可以产生真实政治后果，不要求优于其他方案。必要时使用拒绝、明确维持现状或合法延期；延期需实际程序允许，不能借同一事件无限推迟。不能通过技术性权限门槛让所有选项锁死。需正式回应与纯不干预不同，实际选项成本须说明。多项必答逐项记录、任意合法顺序处理，依赖关系显式；解决一个不清除其他阻断。已处理事件历史回顾只读。
若事件规则无法构成合法零资源回应，视为设计错误，不能给玩家悄悄自动选择、发放额外行动或假装已解决。实现验收须覆盖资金为零、行动为零、授权不足、多个同时到期及月底途中产生必答。历史触发时点与本局实际前提分开记录；具体历史事件、触发概率仍待设计。

### 3.5 长期工作默认候选（M-06/M-14）
建议统一普通长期工作：当月确认安排并预留启动行动及首期资金，月末校验并启动，次月为首个执行月；次月月初支付首期及其后每个执行月的当期费用，月底登记实际进展。若特定工作确需即时启动，作为明确规则例外，单独给出当月支付和起算，不能由UI文字临时决定。仅预留已承诺的最近一期及实际固定启动费（如有），不预留全部未来预测费用；首次预留资金转支付不二次占用。启动时扣除安排的行动成本；启动前撤销释放预留；未能启动则保留失败原因并释放尚未发生消耗。具体月费、启动费和行动成本不在此冻结。
例：1月安排一个3个月有限期项目，2月–4月为实际执行窗口；首期预留1月建立，2月初支付、2月底登记第1个已执行月。预测总成本仅按已知方案和计划估算。项目若资金不足，建议进入“待经费处理/暂停”而非自动获得效果或形成负余额；未付当期不计付费执行进展，已经发生的义务单独记录，通知玩家并提供缩减、终止或其他实际可行路径。是否自动恢复、暂停能否延长计划结束日、合同义务及失败影响待定；暂停期间不自动重置既有成果。变更/终止默认从下一执行月起生效（候选），仅未支付且尚可取消的预留释放；真实已投入费用不返还，调整是否消耗行动及具体政治代价待确认。持续活动没有虚构完成百分比；谈判记录的是往来、条件及等待，不默认视为持续付费项目。仅当实际存在费用或工作责任时使用对应项目规则。
