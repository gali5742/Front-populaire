# Phase 0.5D · D2 政治主体与议题模型
版本 v0.2；2026-11-27；CANDIDATE / OWNER REVIEW REQUIRED。D1于本轮获用户“基本同意”，按原则通过处理，既有具体默认值可供后续设计引用，不视为全部参数冻结或实际运行验收。本文件为D2新增候选，不修改史料、不开始游戏代码。

## 1. 设计目标与范围
依据GAME_DESIGN、SIMULATION_SPEC、D01–D77、UI03及UI_SUITE_V2_SPEC；尤其D46/D48/D49/D50/D54/D55/D61/D74。玩家采取SFIO中央领导层的决策视角，不是全体CAP成员的共同意志，也不代表全党所有成员。拒绝把单一好感度隐藏于后台作为主要决策机制，也避免全量个人代理。保留有限的隐性局部评估和不确定性，不增加通用资源或公开评分仪表盘。
| 对象 | 运行粒度 |
|---|---|
| SFIO中央领导层 | 玩家决策，受党内授权和程序约束 |
| 主要派系、其他主要政党 | 具政治目标与自主行为的主体 |
| 重要地方联合会、工会、社会组织 | 具自主性，按相关事务参与；其余组织可聚合 |
| 议会两院、内阁、党内委员会 | 议事/执行机构；按组成、程序与权限产生集体决定，不假定独立统一人格 |
| 政治人物 | 默认身份、职务、成员关系；确有必要的领袖或关键个人才单独决策 |
| 选民、普通成员 | 群体与抽象选区；不逐人模拟 |
玩家可在其实际权限内发起议程、提出方案、执行已有授权及争取政治支持；CAP是依真实组成与程序产生集体决议和授权的议事机关，玩家不能直接指定表决结果。总书记及其他领导职务是拥有具体权限的职位，不将玩家绑定到特定个人、固定派系或永久多数派。领导层更替、失去多数及控制范围如何传导由D3核定，当前不预先指定玩家自动继任或改控某派。主体类型不决定其永久存在或固定意见；同一人物多重身份不产生多份独立行动权。多数派为可变联盟/描述，而非固定派系。机构、主体与成员关系分开，任免及代表权有有效时段；D3/D5定义具体制度。任何主体的正式立场不自动代表全体成员。

## 2. 主体与议题的最小记录
主体保留稳定ID、类型、角色与所属关系、少量有内容的长期政治目标/底线、实际承诺/义务、相关的组织能力和制度权限。目标按作用范围定义并允许随实际政治过程改变；能力使用具体事实（议席、可组织的活动、职务等），不能转成通用可消费政治点数。初版不设普遍忠诚度、影响力、激进度或全局关系分；如试验确需隐性量，须证明它对特定行为有独立解释力，列出范围、来源和校准方法。
议题以实际争议及可辨认的方案为中心，不是每个月自动生成的任务，也不是一条抽象政策轴。字段：稳定ID、起因及相关事实、具体问题、相关主体、方案及版本、关联授权/协议/议案、程序状态及到期检查点（实际存在才填）、已形成的决定、后续事项。正式议案、动议和协议分别保留独立记录，可共享议题ID；议题本身无独立法定权力。修订方案须有新版本，旧承诺不自动扩展。
**有限反建议空间（v0.2）**：每个议题定义有限、结构化且有政治含义的可协商条款及合法取值（例如范围、具体协作方式、期限、例外及执行责任），不限制为统一三个合作档次；反建议须通过条款兼容、权限和时限检查。实质相同的版本按规范化条款识别，拒绝记录与版本绑定；没有新事实、新授权或实质条款变化，不重复提出已明确拒绝的版本。单次磋商实例须有明确收束条件：实际硬截止、该类事务的有效轮次上限或可穷尽的有效变体空间；即使有新事实也不可无期限刷新上限或越过实际截止。耗尽空间、超时或正式退出时，记录磋商未果、退出或已有部分结果；已发生声明、让步、承诺及成本不被抹去，不将未缔结事项默认为有效协议。以后确有新的政治机会才另开关联实例，不能靠自动重开规避收束。具体条款集合、各类轮次和协议成立程序留D4/D6；不设统一三轮或五轮。多方同意须对应同一有效版本及所需各方程序，不能拼接不同版本的接受记录。
例（虚构演示）：议题“开展联合反法西斯活动”，方案可分别为共同声明、协调各自活动、建立持续组织协作；不能用一个支持/反对标签覆盖所有条款。某主体支持共同声明不必接受长期组织协作，支持组织协作也不自动同意选举退选或入阁。

## 3. 四层政治状态，不相互代替
| 层 | 记录内容 |
|---|---|
| 主体内部倾向 | 对具体议题及方案的判断、关切、可接受条件；可有内部分歧 |
| 已表达的政治意见 | 实际声明、报告、会议意见、接触反馈及表达日期、范围 |
| 正式决定或义务 | 由真实权限及程序产生的决议、协议、授权与限制，记录效力、版本、范围、期限 |
| 实际行为 | 投票、履行、拒绝、违约、联合活动、组织变化等发生事实 |
内部倾向可变化但不自动公开；表达不等于正式承诺，承诺不等于履行，履行也不等于永久认同。支持目标、支持当前方案、愿意采取行动必须分开。缺乏意见、已知未形成意见、存在内部异议、等待回复、未掌握意见不同；不统一归成中立。表达意见不必硬编码为赞成/反对三类，后台评估和可见文字允许具体条件。

## 4. 自主决策候选算法
采用“候选行为→合法性→具体议题评估→选择与时序→制度执行→反馈”的有限规则流程，非全量效用最大化。
1. 只对触发相关事务的主体生成少量有意义候选行为，例如发表意见、提出条件、接触、提交动议、参与协商、维持原状。无实际事务可不行动；不每月强制每个主体表态。允许非玩家发起事件。
2. 采用四层统一裁决骨架（v0.2候选），按层处理约束，不以固定词典序比较所有政治价值：
   - Tier 0：硬性制度合法性和实际可行性。排除无权、程序不符、已过期限或客观不可执行的行为；合法的争取授权、改策程序可另作为候选，不等同已获得授权。
   - Tier 1：政治约束处理。识别现行政治底线、正式义务及内部授权之间的冲突。制度性禁止仍属于Tier 0；正式路线可经相应程序改变；主体当前底线须有适用条件，变化须有政治原因；普通偏好可以妥协。对冲突生成合法的拒绝、修订、改策、重新授权或承担违约后果等路径。底线与正式义务不预设永久优先顺序；不能把偏好直接提升为硬性禁令，亦不能无视仍有效的限制。违约路径须是该主体实际能够实施的行为，并记录后果；不是一律允许绕过制度。
   - Tier 2：局部政治判断。在上述合法且合理的路径中，按当前主要关切、长期目标、组织利益、实际风险及相关内部异议择优。可用少量序数描述局部判断，理由与方案版本关联；不设跨议题加总的政治效用或统一关系分。依据主体当时可知的信息，不使用其他主体未披露的秘密。
   - Tier 3：最终选择。先按可说明的情境优先规则处理同等合理路径（如维持现状、既有承诺），必要时拒绝、依法延后或引入有限随机性。延期不得跨越真实期限；随机仅在合法且政治合理的候选集合内进行，以稳定事务ID及可复现种子记录；查阅、重复提交、读档不重抽。具体各主体优先顺序及概率留相关子系统校准。
3. 不为每个主体×议题组合建立独立规则树；复用上述约束类型及行为模板，仅为有实质区别的制度/议题添加规则，例外须记录适用条件。优先级冲突不能被统一数值评分掩盖。初版规则须能说明为何排除行为、为何保留候选；解释的对外可见范围遵守第6节。
4. 选中的行为经过真实机构流程，产生实际决定或等待状态，再按D1结算并记录。任何主体都不能凭评估直接生成自己无权作出的法定结果。回复应尽量形成有信息价值的实际表达或可知事实反馈；不将完整内部评估向玩家显示，具体标准见第6节。具体投票聚合、党纪、选票转移、协议生命周期与内阁权限留D3–D6。
例（假设、非历史重建）：党A同意共同声明但不接受持续组织协作；玩家先取得党内授权，再向A提出持续协作。A可能拒绝、提出仅发表共同声明的反建议或延迟回复。玩家授权不保证A接受，A的拒绝不撤销已发生的接触成本。同样，接受共同声明不应无因提高其他不相关议题的通过率。

## 5. 变化、记忆及自主行为调度
态度变化必须可追溯至具体刺激：新事实、经济与社会变化、政治行动及其结果、承诺履行/违约、领导更替、组织决定。主体记忆保留有实质关联的记录；不因每月自动刷新全部评价，也不因一次合作普遍上涨。跨议题影响需显式因果桥梁，例如违反同一联盟承诺影响下一轮履约判断，而不是全局好感下降。过时判断可因新信息重估，长期政治立场可逐步改变，不冻结人物历史路线。
建议D1检查点中按实际触发与依赖调度：收到提案时产生合法回应或等待，制度表决到期按实际程序，月内/月底仅检查相关主体的可行动事务。先确定有权作出行为的主体及其当时信息，再处理行为与反馈。对相互依赖且同时到期的行为使用同一检查点的既定信息截面形成意向，再按制度或明确依赖顺序执行；不因列表顺序使后行动者自动拥有先行动者的秘密。反应产生后续事务有稳定因果ID与明确时序，重复触发去重；连续反应须遵守截止、合法性和有限处理边界，禁止同一原因无限循环。非玩家主体不使用玩家的2次行动额度，不建立所有主体统一的行动点系统；受实际组织能力与制度时序制约，避免无限行为。具体每类主体的活动规模、频率和同点冲突规则待校准。不能为了限制计算随意丢弃已产生的正式义务或必答事项。
**月末调度隔离（v0.2）**：常规非玩家提案及衍生事务若在月底结算中产生，默认排入下次正常决策窗口；实际行为发生及披露时点不改变。只有将错过真实必答截止或政治程序节点时才中断结算，不把普通邀请、报告、危机名称或等待回复直接标为必答。玩家主动接触后的即时反馈仍可即时显示。调度以D1 v0.2第3.1节为共同规则，禁止通过延期或循环重开绕过硬截止。
派系形成/分裂/重组应有持续的具体路线分歧、组织基础、实际组织行为及制度记录作为依据；本轮仅提供触发接口，不确定分裂概率、阈值或固定三派。地方组织与工会有独立诉求；中央支持不直接指挥其行为。

## 6. 信息模型与玩家可见性
沿D1三层：历史证据、本局后台事实、玩家所知记录。后台事实包括当事主体未公开状态；主体自己的判断也基于其可知信息。每条可知信息记录事件发生时点、观察/报告时点、来源/渠道、接收者、可见范围、关联事实或陈述、有效时段、修订及冲突关系。初版建议用公开声明、正式党内报告、直接接触、公开程序、间接报告等来源类别及定性时效；不新增需要玩家经营的情报资源，不为所有信息构造精密概率。正式报告能证明报告存在，不一定证明报告内容完全真实；可存在来源冲突或陈述与实际行为不一致。没有新信息不自动显示已改变的隐性立场。
UI的“已知政治意见”展示表达主体、具体意见、必要理由；如实际信息过时/仅为间接报告则适当注明。当前后台倾向不可直接读出。正式公开决议和投票结果按真实披露时点可见；内部组织资料按中央身份及信息渠道确定。若对方尚未形成意见本身不为玩家所知，只能显示未获知或未收到回应。等待回应来自实际已发出的请求；不能以未获知推断拒绝或尚未决定。
统一可见性查询覆盖简报、摘要、检索、计数、筛选、关联入口、禁用原因、方案预测、历史记录、通知；同一政治事实可多页展示但共用权限与时点，不经隐藏条目数量或排序泄露秘密。不可见事实可以影响实际政治结果，但可知反馈只依据实际获知的内容。**反馈标准（v0.2）**：当主体决定对外回应时，可同时形成结构化的已表达意见记录（表达主体、方案版本、回应类别、实际公开声明或私下告知的理由/条件、时间、渠道、接收范围）。初版行为模板应尽量给出可供下一次决策使用的具体条件、保留意见或公开理由，而不是一律只报成败；这些表达可以具有策略性或不完整，不等同于后台真实判断。若仅明确拒绝且未说明理由，应显示拒绝及未提供进一步理由，不伪造说辞；尚未收到回应则显示等待，不能把明确拒绝与尚未接受混同。前后表态不一致时保留各次记录及时间，按实际可见性展示。相关后续方案仅依据实际可用权限、事务和已知信息显示，不暗示秘密底线或保证成功。不为填充反馈而凭空添加主体未作出的陈述。开发史料未核须在数据层/研究记录区分，不伪装成游戏情报不足，也不由生成文案填造。
历史资料允许当时可知的背景，不提前展示真实历史未来事件及预设结果。历史日期不等同档案可见日期；D8确定最低开局证据及访问规则。经济与社会支持的具体统计、国际信息边界由D7及相关议题进一步细化。前台不提供精确支持率、内部评分或未核定的推断票数。

## 7. 最小联动走查（虚构示例，非历史记录）
玩家提出联合反法西斯活动→现行授权只允许接触，正式承诺需要党内议事→其他主体可在接触时表达不同条件→玩家选择修订、争取授权或不继续→合法提出方案后等待回复→对方选择接受部分条件、反建议或拒绝→只有真实有效协议产生承诺→工会根据自身诉求决定是否参加；协议、行为与后续报道分别记录。若共同活动成功，不自动保证议会支持、选举退选或内阁参与。若工会自主组织活动，也可能反过来触发本党需回应的事务。依D1 v0.2第3.6节，区分实质主动干预、既有授权执行、正常程序与事务回应；不因接触、了解条件、授权、正式提议、反建议、确认等步骤数量机械扣除行动，也不把整个议题默认免费。D3–D6必须在60个月、每月2次的实际预算下验收关键流程成本，具体收费节点后续确定。
